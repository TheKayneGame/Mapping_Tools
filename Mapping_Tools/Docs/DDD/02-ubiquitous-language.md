# Ubiquitous Language

This glossary defines canonical terms for future DDD design and migration.

## Core Terms

- **Beatmap**: The full editable map artifact, including object lists, timing data, storyboard/events, and metadata/difficulty sections.
- **Beatmap Section**: Named configuration segment of a beatmap (`General`, `Editor`, `Metadata`, `Difficulty`, etc.).
- **Hit Object**: Time-based gameplay object (circle, slider, spinner, hold note) with position and hitsound semantics.
- **Timeline Object**: Expanded playable event representation derived from hit objects and timing.
- **Timing Point**: Control point defining tempo, inherited behavior, kiai, meter, and sample defaults.
- **Redline**: Uninherited timing point representing base tempo/meter section.
- **Greenline**: Inherited timing point used for velocity/effect/sample behavior.
- **Beat Divisor**: Rational snapping resolution unit used in resnapping decisions.
- **Resnap**: Move time/value to nearest valid timing grid point under configured divisors.
- **Slider Velocity (SV)**: Effective speed modifier used in slider temporal/path behavior.
- **Sample Set**: Primary sample family selection for playback context.
- **Addition Set**: Secondary sample family for layered playback.
- **Custom Index**: Numeric sample bank index used for custom sample lookup.
- **Mapset**: Collection of beatmaps that share metadata and audio context.

## Context-Specific Terms

### Beatmap Composition Context

- **Metadata Identity**: Title/artist/creator/source/tag identity values attached to a beatmap.
- **Difficulty Profile**: Difficulty settings (`CS`, `AR`, `OD`, `HP`, multipliers, tick rates).
- **Colour Scheme**: Combo and special colours assigned to gameplay representation.

### Timing & Rhythm Context

- **Snap Leniency**: Allowed tolerance window for resnap eligibility.
- **Tempo Signature**: Musical meter representation used by timing points.
- **Timing Reconstruction**: Regeneration of timing point sets from domain intents.

### Hitsound Context

- **Hitsound Resolution**: Decision process for final sample played at a timeline moment.
- **Body Hitsound**: Hitsound generated by slider body ticks/repeats.
- **Muted Event**: Event intentionally set to low/zero effective volume.
- **Unused Sample**: Asset not referenced by any playable or storyboarded sound event.

### Map Maintenance Context

- **Cleanup Policy**: Explicit set of map normalization rules for maintenance.
- **Consistency Repair**: Correction of known invalid or risky object ordering/state.
- **Normalization Run**: End-to-end cleaning execution instance over one beatmap.

### Tool Runtime Context

- **Tool Module**: Deployable tool package exposing domain and application capabilities.
- **Tool Registration**: Explicit declaration of tool capabilities and entry points.
- **Execution Mode**: GUI or CLI host path used to run the same use case.
- **Use Case Contract**: Input/output boundary between host/framework and application layer.

## Name Normalization Rules

- Use `Beatmap`, not `Map` when referring to the domain aggregate.
- Use `Timing Point`, not generic `Point`, when discussing rhythm control semantics.
- Use `Resnap`, not `Fix timing`, when operation is grid-alignment based.
- Use `Cleanup Policy`, not `Cleaner args`, when discussing business intent.
- Use `Tool Module`, not `View`, for architecture-level conversation.

## Ambiguity Resolution

When a term has multiple meanings:
- Prefer the context-qualified form (`Timing Point`, `Timeline Object`, `Tool Module`).
- If still ambiguous, add the context prefix (`Hitsound.Sample Set`, `Timing.Beat Divisor`).
